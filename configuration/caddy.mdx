Lyra uses [Caddy](https://caddyserver.com/) as its public-facing reverse proxy, handling TLS termination, HTTP/3, compression, and load balancing across all backend services. Caddy listens on ports **443** (HTTPS) and **80** (HTTP → HTTPS redirect) and is managed by systemd.

<Warning>
  The Caddyfile at `/etc/caddy/Caddyfile` is **fully generated by `setup.sh`** and will be overwritten on every re-run. Do not edit it manually. A timestamped backup is made before each overwrite (`/etc/caddy/Caddyfile.bak.<epoch>`).
</Warning>

## Key Features

### On-Demand TLS

Caddy uses on-demand TLS so that certificates are provisioned automatically per SNI hostname on first connection rather than pre-declared. Before issuing a certificate Caddy calls the `tls-approval` service:

```
on_demand_tls {
    ask http://127.0.0.1:3001/
}
```

The `tls-approval` service (port 3001) validates that the requested hostname is associated with this Lyra instance before Caddy proceeds with the ACME challenge.

### HTTP/3

All server blocks advertise HTTP/1.1, HTTP/2, and HTTP/3:

```
servers {
    protocols h1 h2 h3
}
```

HTTP/3 requires UDP port 443 to be open. `setup.sh` adds the necessary UFW rules when UFW is active.

### Compression

Zstd and gzip compression are applied to all routes **except** `/stream/*`. Stream routes are excluded because HLS segments are already compressed video data; double-compressing them wastes CPU with no size reduction.

```
@compressible {
    not path /stream/*
}
encode @compressible zstd gzip
```

### Load Balancing

Caddy sits in front of two internal load-balancer endpoints:

| Endpoint | Backend instances | Policy |
|---|---|---|
| `http://127.0.0.1:4000` | Mochi (`127.0.0.1:4100`–`4100+N`) | `least_conn` |
| `http://127.0.0.1:4001` | Nuru (`127.0.0.1:4200`–`4200+N`) | `least_conn` |

The `:443` block references these virtual upstreams directly with `least_conn` and unhealthy-instance removal:

- **Health check**: `GET /health` every 10 seconds
- **Failure threshold**: `unhealthy_request_count` is set proportionally to available RAM per instance (calculated by `setup.sh`)
- **Removal duration**: unhealthy instances are removed for `10s` (`fail_duration 10s`)

The HLS stream route uses **session affinity** (`lb_policy query session`) so that successive segment requests from the same player session hit the same Mochi instance and share its RAM cache.

## Internal Virtual Hosts

Two internal-only virtual hosts provide unencrypted load-balancer endpoints reachable only from localhost (bound to `127.0.0.1`):

```
http://127.0.0.1:4000  →  Mochi instances  (least_conn)
http://127.0.0.1:4001  →  Nuru instances   (least_conn)
```

These are used by the Node.js server and for internal health polling.

## Route Table

All public routes are handled in the `:443` block. Routes are evaluated in order; the first match wins.

| Path pattern | Backend | Notes |
|---|---|---|
| `/<wisp-path>/*` | Nuru (`127.0.0.1:4200+`) | Random hex path set at build time; WebSocket upgrade |
| `/!!raw/*`, `/!!/*`, `/!!folio/*`, `/!cover!/*` | Mochi (`127.0.0.1:4100+`) | Game proxy and folio routes |
| `/stream/*` (excluding `/stream/anime*`) | Mochi — session affinity | HLS segment delivery; `flush_interval -1` |
| `/stream/anime*` | Lyra (`127.0.0.1:4444`) | Anime player HTML page |
| `/assets/*`, `/b/*`, `/bmux/*`, `/epoxy/*`, `/libcurl/*` | Lyra (`127.0.0.1:4444`) | Static assets served over h2c |
| `/api/auth/*` | CloudSync (`127.0.0.1:4005`) | Authentication API |
| `/api/sync/*` | CloudSync (`127.0.0.1:4005`) | Sync data API |
| `/api/anime/*` | Isao (`127.0.0.1:6001`) | Anime metadata API |
| `/health` | Lyra (`127.0.0.1:4444`) | Global health check |
| `/lyra/health` | Lyra (`127.0.0.1:4444`) | Lyra-specific health check (rewrites to `/health`) |
| `/eturnal/health` | Lyra (`127.0.0.1:4444`) | TURN server liveness (proxied via Lyra) |
| `/tls-approval/health` | tls-approval (`127.0.0.1:3001`) | TLS approval service health |
| `/cloudsync/health` | CloudSync (`127.0.0.1:4005`) | CloudSync health |
| `/isao/health` | Isao (`127.0.0.1:6001`) | Isao health |
| `/mochi/health` | Mochi (`127.0.0.1:4100+`) | Mochi aggregate health |
| `/nuru/health` | Nuru (`127.0.0.1:4200+`) | Nuru aggregate health |
| `/s` | Lyra (`127.0.0.1:4444`) | Search suggestions page |
| `*` (fallback) | Lyra (`127.0.0.1:4444`) | Main application |

<Note>
  The Wisp path (`/<wisp-path>/`) is a 64-character random hex string generated at deploy time and baked into the client bundle. It is not `/w` in production — that default only exists in the source `config.toml` template.
</Note>

## Transport Settings

Long-lived backends (Mochi and Nuru) use extended keepalive settings to reduce connection overhead across many concurrent proxy streams:

```
transport http {
    keepalive                  120s
    keepalive_idle_conns       4096
    keepalive_idle_conns_per_host 1024
    dial_timeout               5s
}
```

Nuru's transport also sets `read_buffer 65536` and `write_buffer 65536` to accommodate large WebSocket frames.

The static-assets and fallback routes for the Lyra Node.js server use `h2c://127.0.0.1:4444` (unencrypted HTTP/2 cleartext), which avoids double TLS overhead on the loopback interface.

## `X-Real-IP` Forwarding

Every `reverse_proxy` block includes:

```
header_up X-Real-IP {remote_host}
```

This allows backend services to read the real client IP from the `X-Real-IP` header. Nuru uses this via `use_real_ip_headers = true`; the Node.js server trusts it from loopback connections only.

## Port 80 Redirect

```
:80 {
    redir https://{host}{uri} permanent
}
```

All HTTP traffic is permanently redirected to HTTPS. Open port 80 in your firewall to allow the ACME HTTP-01 challenge during certificate issuance.

## Systemd Override

`setup.sh` writes `/etc/systemd/system/caddy.service.d/override.conf` to raise the file-descriptor limit and suppress proxy environment inheritance:

```ini
[Service]
Environment="NO_PROXY=127.0.0.1"
LimitNOFILE=1048576
```
