Lyra is a privacy-first, self-hosted web proxy designed to give you full control over your browsing infrastructure. Rather than routing your traffic through a shared third-party service, you deploy Lyra on your own server — getting a polished UI, thousands of aggregated browser games, free anime streaming, cloud-synced settings, and even functional Chrome extension support, all under the AGPL-3.0 license.

## Architecture

Lyra is composed of several focused services that work together behind a Caddy reverse proxy. Understanding the role of each component helps when scaling, debugging, or extending the platform.

| Component | Language | Role |
|---|---|---|
| **Mochi** | Rust | High-performance reverse proxy and anime stream cache. Runs as multiple systemd-managed instances behind Caddy for load balancing. |
| **Nuru** | Rust | Wisp-compatible WebSocket tunnel. Provides the low-latency connection path used by the Folio service worker in the browser. |
| **Folio** | TypeScript / Rust (WASM) | Service-worker-based JavaScript rewriter. Rewrites page content client-side using a WASM engine compiled from Rust nightly. |
| **Rivet** | TypeScript | Chrome extension runtime layer. Intercepts extension APIs and bridges them into the Lyra environment. |
| **CloudSync** | Rust | Persistent sync service backed by SQLite. Handles auth, bookmarks, and settings sync across sessions and devices. |
| **Isao** | Rust | Anime metadata and catalogue service. Powers the streaming library and search within the Lyra UI. |

All public traffic enters through **Caddy** on ports 443/80, which terminates TLS (including on-demand TLS for custom domains), applies compression, and routes requests to the appropriate backend service. A separate **eturnal** TURN server (port 3478) handles WebRTC relay for video streaming.
